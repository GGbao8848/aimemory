# 沉淀：把关键信息存入记忆库

写入流程。核心工具是 `add_memory`（异步）+ `get_event_status`（轮询到底）。

## 何时做：先过一道「长久 × 广度」门槛

这个库的定位是**跨机器、跨项目、长久的记忆**——写之前先问一句：「三个月后换台机器、换个项目，
这条还有用吗？」按答案分流：

| 内容类型 | 去处 |
|---|---|
| **跨机器/跨项目事实**：主机与网络拓扑、账号、全局工具链、个人偏好、通用踩坑（如 Git Bash 引号问题） | ✅ 写入本库（不带 agent_id 或带 `agent_id: "global"`） |
| **长期项目的关键结论**：会延续数月的项目，其架构决策、关键环境、复现路径 | ✅ 写入本库，**务必带 `agent_id: "<项目名>"`** |
| **短期项目的实现细节**：几周就结束的项目里的路径/版本/接口参数/调试过程 | ❌ 不进本库——写进该项目的 `AGENTS.md`/`CLAUDE.md`（随项目走、随项目亡） |
| 任务状态、操作过程、寒暄、代码/文档里随时能查到的东西 | ❌ 哪里都不存 |

- 用户说"记住"但内容低于门槛时，照存（用户显式要求优先），但**聚合**：同主题多条细节合并成
  一条综合陈述提交，不要一事一条刷库。
- 项目相关的记忆**总是带 `agent_id: "<项目名>"`**——这是日后按项目检索、批量清理的唯一抓手。

## 步骤

1. **整理内容**：多轮对话 → `messages` 数组（LLM 会提炼成多条结构化记忆）；单一结论 → `text`。

2. **调用 `add_memory`**（项目相关带 `agent_id`）：

   ```json
   {
     "text": "EdgeVision 项目环境：Android SDK 在 C:\\tools\\android-sdk，Gradle 8.9，Maven 走阿里云镜像，dl.google.com 需走 127.0.0.1:7890 代理",
     "agent_id": "EdgeVision"
   }
   ```

   或 `{"messages": [...]}`；可带 `metadata`（如 `{"source": "zcode"}`）透传到每条产物。

3. **轮询到终态（务必，勿谎报）**：`add_memory` 一律异步，返回 `{event_id, status:"pending"}`。
   用 `get_event_status` 轮询（最多等 ~30s）：
   - `done`：拿到提炼出的记忆列表，向用户展示/确认已保存；
   - `failed`：提炼失败（LLM 不可用或无有效产出），**素材未入库**——如实告知，可稍后重试。

## 约束

- **只存结论要点**：不整段对话双投（服务端消解会判 NOOP 拦下重复，但双投浪费判定 token）。
- **敏感凭据按部署策略**：本服务定位内网自托管（本地模型），默认（`SENSITIVE_MODE=allow`）凭据
  可按原文入库，不必回避；若服务端配置为 `redact`，提炼层会自动脱敏，无需在素材里自行处理。
- **归属**：记忆归当前登录用户/Token 持有者，全端共享；项目维度用 `agent_id` 标，无需标记来源机器。
- 保存失败如实告知，不谎报成功。
