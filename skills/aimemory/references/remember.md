# 沉淀：把关键信息存入记忆库

写入流程。核心工具是 `add_memory`（异步）+ `get_event_status`（轮询到底）。

## 何时做

- 用户说"记住"、"别忘了"、"记一下"、"写进记忆"、"存一下"
- 对话形成可复用的关键结论：决策及其理由、配置、踩坑教训、方案取舍
- 用户表达持久偏好、事实、项目背景

不值得存：一次性对话（"今天天气"）、寒暄、可随时从代码/文档查到的东西。

## 步骤

1. **整理内容**：多轮对话 → `messages` 数组（LLM 会提炼成多条结构化记忆）；单一结论 → `text`。

2. **调用 `add_memory`**：

   ```json
   {
     "messages": [
       {"role": "user", "content": "..."},
       {"role": "assistant", "content": "..."}
     ]
   }
   ```
   或 `{"text": "要记住的内容"}`；可带 `metadata`（如 `{"source": "zcode"}`）透传到每条产物。

3. **轮询到终态（务必，勿谎报）**：`add_memory` 一律异步，返回 `{event_id, status:"pending"}`。
   用 `get_event_status` 轮询（最多等 ~30s）：
   - `done`：拿到提炼出的记忆列表，向用户展示/确认已保存；
   - `failed`：提炼失败（LLM 不可用或无有效产出），**素材未入库**——如实告知，可稍后重试。

## 约束

- **只存结论要点**：不整段对话双投（服务端消解会判 NOOP 拦下重复，但双投浪费判定 token）。
- **不存敏感明文**：默认不存完整密码，可存"存在哪/用户名"，除非用户明确要求。
- **归属**：记忆归当前部署的个人账本，全端共享，无需标记来源。
- 保存失败如实告知，不谎报成功。
