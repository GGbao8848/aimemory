# 召回：把相关记忆注入上下文

只读流程——只检索，不写入、不删除。核心工具是 `search_memories`。

## 何时做

- 开始新任务、切换项目或上下文时
- 用户说"之前/上次/以前/我记得/我们讨论过"
- 任务涉及历史决策、偏好、配置、踩坑经验、个人习惯或团队约定

## 步骤

1. **提取主题**：从当前用户消息/任务中抽出关键词——文件名、模块名、功能领域、技术栈、人名、项目代号。

2. **并行检索**：按 2–4 个角度调用 `search_memories`（尽量并行，各取 top 5）：

   | 查询角度 | 示例 | 目的 |
   |---|---|---|
   | 项目/模块名 | `"aimemory 部署"` / `"bip 报工"` | 架构与配置 |
   | 技术/工具 | `"pm2 管理"` / `"embedding 服务"` | 技术决策与偏好 |
   | 用户提到的实体 | 刚出现的文件名/人名 | 相关背景 |
   | 宽泛上下文 | 任务的一句话总结 | 兜底召回 |

3. **去重合并**：按记忆 id 去重（结果里带 id）。

4. **输出紧凑上下文块**（最多 10 条，只留与当前任务真正相关的）：

   ```
   [aimemory 记忆] 已加载 <N> 条相关记忆：
     • <记忆内容> [id: <短id>]
   ```

5. **零结果时保持沉默**：不输出空上下文块，不说"没有找到记忆"。

## 约束

- **只读**：绝不调用 `add_memory` / `update_memory` / `delete_memory`
- **最多 10 条**：避免污染上下文
- **融合不引用**：把内容融入回答，除非用户要求，不逐条罗列来源
- 记忆是历史快照，**用前判断时效性**（涉及密码/端口可能已变更），必要时提醒核实
