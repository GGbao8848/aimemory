# 单点登录 / 单点登出（SSO / SLO）设计

> aimemory 与 BR-Agent（Web 9005 / 桌面客户端）通过同一 Keycloak（realm br-platform）实现浏览器侧单点登录与单点登出：登录任一端，其他端免密直达；任一端登出，三端同时退出。

## 架构总览

```
                    同一个 Keycloak（10.1.20.132:6543 / realm br-platform）
                                │  SSO session cookie（按 host 域）
   ┌──────────────┬─────────────┴───────────────┬──────────────┐
   │ BR-Agent Web │        aimemory Web         │  桌面客户端   │
   │   :9005      │          :18543             │  (Electron)  │
   │ client=br-agent│      client=aimemory-web  │ client=br-agent
   └──────┬───────┘      └──────────┬───────────┘ └──────┬──────┘
          │ front-channel(SSE 替代)  │ front-channel      │ back-channel
          ▼                          ▼                    ▼
   BR-Agent server :9004  ◄──── Keycloak end_session  ────┘
      │  /api/auth/kc-logout（验签 logout token）
      ├─► SSE 广播 → Web 前端清 token 退出
      └─► WS 广播  → 桌面客户端清本地 token 退出
```

## SSO 免密登录

- **前提**：aimemory 的 `KEYCLOAK_URL` 必须与 BR-Agent 用**同一 host**（`10.1.20.132:6543`，非 `localhost`）——Keycloak 的 SSO session cookie 按 host 域存储，host 不一致则读不到对方登录建立的会话。
- **aimemory**（`src/web/static/app.js`）：每次打开都无条件 `location.href='/auth/login'` 走 Keycloak；已登录过 → 免密回跳（callback 带 `?logged=1`，前端据此避免死循环）；未登录 → Keycloak 登录页。
- **BR-Agent Web**（`apps/web/src/App.tsx`）：`authed=false` 且 `sessionStorage` 无 `kc_auto_login_attempted` 标记时自动跳 Keycloak（免密回跳）；标记防循环，登录按钮点击时清除标记。

## SLO 单点登出

### 三种通道（Keycloak end_session 触发）

| 通道 | 目标 | 机制 |
|---|---|---|
| **front-channel** | aimemory Web | Keycloak 以 iframe 加载 `http://10.1.20.132:18543/slo-logout`（`GET /slo-logout` 清 aim_session cookie，返回 200） |
| **back-channel** | 桌面客户端 | Keycloak 服务端 POST logout token 到 `http://localhost:9004/api/auth/kc-logout` → server 验签 → WS 广播 `{type:"logout"}` → 桌面清本地 token |
| **SSE（back-channel 派生）** | BR-Agent Web | br-agent 配置 back-channel 后 Keycloak **跳过 front-channel iframe**，故 Web 前端经 `/api/sse/logout` SSE 订阅，由 server 在 back-channel 广播时推送登出 |

### BR-Agent server（`apps/server/src/auth/kc-logout.ts` + `src/index.ts`）

- `POST /api/auth/kc-logout`：验签 logout token（jose + JWKS，校验 issuer/audience=br-agent/backchannel-logout 事件）→ `broadcastLogout()`（WS）+ `notifySseLogout()`（SSE）
- `GET /api/sse/logout?token=`：SSE 订阅端（query token 校验），服务端广播时推送 `data: logout`

### BR-Agent Web（`apps/web/src/App.tsx`）

- SSE 订阅（已登录时连接，断线 5s 重连）；收到 `logout` → `clearTokens()` + 切回登录页
- 另监听 `storage` 事件（front-channel iframe 清 localStorage 的兜底，两种通道互备）

### 桌面客户端（`apps/desktop/src/main/`）

- `slo-ws.ts`：主进程常驻 WS 连接 `/api/ws/client?token=`（断线指数退避重连 + 25s ping），收到 `logout` → 清 token-store + 通知渲染层回登录页
- `auth.ts` `logoutFromKeycloak()`：桌面登出时系统浏览器打开 Keycloak `end_session`（带 id_token_hint），触发其他端的 SLO
- `token-store.ts` 保存 idToken；`index.ts`/`ipc.ts`/`preload.ts`/`App.tsx` 接线（`auth:logout-remote` 事件）

## 三端行为矩阵

| 操作 | BR-Agent Web | aimemory Web | 桌面客户端 |
|---|---|---|---|
| 登录任意端 | 其余端免密直达（SSO） | 同左 | 桌面走系统浏览器，浏览器已登录则免密 |
| 在 Web 登出 | 清 localStorage + 跳 end_session | front-channel 清 cookie 退出 | back-channel 广播清 token 退出 |
| 在 aimemory 登出 | SSE 广播清 token 退出 | 清 cookie + 跳 end_session | back-channel 广播清 token 退出 |
| 在桌面登出 | SSE 广播清 token 退出 | front-channel 清 cookie 退出 | 清 token + 系统浏览器跳 end_session |

## Keycloak client 配置

由 `scripts/setup-keycloak.mjs` 幂等配置（admin API，GET 完整对象→PUT）：

| client | 配置 |
|---|---|
| `aimemory-web` | `frontchannel.logout.url = http://<IP>:18543/slo-logout` |
| `br-agent` | `frontchannel.logout.url = http://<IP>:9005/slo-logout`（当前被 back-channel 跳过）、`backchannel.logout.url = http://localhost:9004/api/auth/kc-logout`、`backchannel.logout.session.required = true` |

> 重跑 `node scripts/setup-keycloak.mjs` 即可应用/修复（需 `.env` 的 `KEYCLOAK_ADMIN_USER/PASSWORD`）。

## 实施中遇到的问题与解决办法

| # | 问题 | 根因 | 解决办法 |
|---|---|---|---|
| 1 | 登录 9005 后打开 aimemory 跳登录页 | aimemory `KEYCLOAK_URL=http://localhost:6543`，SSO cookie 按 host 域存储，与 9005 的 `10.1.20.132:6543` 不同域 | `.env` 统一为 `http://10.1.20.132:6543` |
| 2 | aimemory 显示 br0004 而非登录用户 br0002 | 旧 aim_session cookie（7 天）直达页面，绕过 Keycloak | `app.js init()` 无条件走 `/auth/login` SSO 校验，callback 回跳带 `?logged=1` 防循环 |
| 3 | aimemory 登出后 9005 不退出 | ① Keycloak 配 back-channel 后跳过 front-channel iframe；② server 415（fastify 无 urlencoded 解析） | ① Web 改经 SSE 推送登出（back-channel 派生通道）；② server 注册 urlencoded content-type parser |
| 4 | back-channel 校验 `Invalid Compact JWS` | 用 `URLSearchParams` 解析 urlencoded，把 JWT 里的 `+` 解码成空格 → token 畸形 | 自定义 parser：手动按 `&`/`=` 切分，value 用 `decodeURIComponent`（只解 %XX，不把 `+` 当空格） |
| 5 | back-channel 校验 `Failed to base64url decode` | 解析器不解码 `%2B`/`%3D`，Keycloak 发送时百分号编码了 JWT | 见 #4 的 `decodeURIComponent`（覆盖两种编码形态） |
| 6 | 登录 18543 后打开 9005 不自动登录 | 9005 前端未登录时只显示登录页，不自动跳 Keycloak | `App.tsx` 未登录自动跳 Keycloak（sessionStorage 防循环） |

## 已知限制

- SLO 覆盖浏览器 SSO 会话；桌面本地持久化 token（tokens.bin）不随浏览器登出自动清除（靠 back-channel WS 推送，桌面在线时生效）。
- 桌面登出时若系统浏览器未持有 SSO 会话（如换浏览器），`end_session` 仅提示、不保证他端退出。
- access token 过期（默认数分钟）不随登出立即失效；他端退出后本地已清，残余 token 由 refresh 失败或到期兜底。
- 前端自动跳 Keycloak 依赖浏览器允许同站 iframe/重定向；极端配置下需手动点登录。
