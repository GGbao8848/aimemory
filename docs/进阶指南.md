## 架构

```
agent / SDK / 脚本 ── POST /v1/memories · POST /v2/memories/search，Authorization: Token m0-xxx
MCP 客户端        ── POST /mcp
        │
        ▼
HTTP Server :18543 (Express)
  /v1 /v2     mem0 形态 REST（Token 鉴权）
  /mcp        MCP Streamable HTTP（7 工具）
  /api/*      管理台自用面（Token 或 Web 会话 cookie）
  /admin, /   Web 管理台（web/ 构建产物 + Keycloak 登录，多租户）
  /auth/*     Keycloak OIDC 登录/登出（/slo-logout 单点登出）
  /healthz    健康检查（db / embedding / llm / 提炼队列积压）
        │
        ▼
SQLite (data/aimemory.db): memories + memories_fts(FTS5) + memory_ops(变更历史)
        + l2_meta(向量维度) + users(Keycloak 建档) + api_keys + sessions + events(异步提炼队列)
        │
        ├─ embeddings/client.js → OpenAI 兼容 /v1/embeddings（语义向量）
        └─ llm/client.js       → OpenAI 兼容 /v1/chat/completions（素材提炼/消解判定）
```

## REST API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/memories/` | add（infer=true 异步提炼 / infer=false 直存） |
| POST | `/v2/memories/search/` | 混合检索（query + filters + top_k） |
| POST | `/v2/memories/` | get_all（filters + 分页，{count, next, previous, results}） |
| GET/PUT/DELETE | `/v1/memories/{id}/` | 单条 / 更新 / 删除 |
| GET | `/v1/memories/{id}/history/` | 变更历史（ADD/UPDATE/DELETE 留痕） |
| DELETE | `/v1/memories/` | 按作用域批量删除（异步，返回 event_id） |
| GET | `/v1/event/{event_id}/` | 异步事件状态轮询 |
| POST/GET | `/api/keys`、`/api/keys/:id/revoke` | Token 管理（管理台自用面） |
| GET | `/api/stats` / `/api/me` / `/api/memories/export` | 统计 / 身份 / 导出 |

完整契约：[docs/api/openapi.json](api/openapi.json)（路径与方法集由测试守护，TS 类型 `npm run types` 生成）。
对接细节（鉴权、filters、错误语义）见 [前端对接.md](前端对接.md)。

## 配置项（.env 关键项）

| 变量 | 说明 |
|---|---|
| `PORT` | 服务端口（默认 18543） |
| `KEYCLOAK_URL` / `KEYCLOAK_REALM` / `KEYCLOAK_CLIENT_ID` | Keycloak 登录（默认 realm `br`，client `aimemory-web`）；未配置时 Web 面不可登录，Token 面不受影响 |
| `PUBLIC_BASE_URL` | 反向代理/容器部署时对外可达地址（拼 OIDC 回调用） |
| `AIMEMORY_USER_ID` | 存量单用户数据归属（仅供 `npm run migrate:owner` 迁移旧数据，不参与鉴权） |
| `LLM_ENABLED` / `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` / `LLM_TIMEOUT_MS` | 提炼用 chat/completions（未启用时 infer=true 写入直接拒绝） |
| `EMBEDDING_ENABLED` / `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` / `EMBEDDING_API_KEY` | 语义检索（不可用自动退关键词；换模型后 `npm run vec:rebuild`） |
| `AIMEMORY_DB` | 数据库路径覆盖（测试用独立库） |
| `L2_*` | 冲突消解开关与 token 预算（全量见 [.env.example](../.env.example) 注释） |

## Keycloak 多租户登录

- Web 管理台经 Keycloak OIDC（授权码 + PKCE）登录，与 BR-Agent 多租户部署共用同一 realm（默认 `br`）：
  同一浏览器登录过任一端，另一端免密直达；任一端登出，各端同时退出（front-channel `/slo-logout`）。
- 机器接入（MCP / `/v1` `/v2` / `/api`）不经过 Keycloak，继续用 `m0-` Token（归属签发用户）。
- client 注册：`.env` 配好 `KEYCLOAK_URL` / `KEYCLOAK_ADMIN_*` 后 `npm run setup:keycloak`（幂等：
  确认 realm 存在 → 注册/补齐 client `aimemory-web`（public + PKCE S256 + 回调地址 + audience mapper +
  front-channel 登出）。Keycloak 26 必须有 audience mapper，否则回调报 missing aud；
  front-channel 登出必须写 `attributes['frontchannel.logout.url']`（顶层字段 KC 26 报 400）。
- 手工注册等价步骤与故障排查：见 [部署-生产机.md](部署-生产机.md)「Keycloak 注册」一节。

### 存量单用户数据迁移（owner → Keycloak 用户）

v0.2 单用户时代的旧数据归属 `AIMEMORY_USER_ID`（默认 `owner`）。迁移流程：

```bash
npm run migrate:owner -- --list          # 1. Keycloak 登录一次（自动建档）后，列出用户与数据分布
npm run migrate:owner -- --to <用户名>    # 2. 先在线备份到 backups/pre-migration-*，再单事务迁移并校验
pm2 restart aimemory-mcp                 # 3. 重启清掉缓存旧身份的 MCP 会话（≤30 分钟自然过期）
```

目标用户已有同名 Token/实体（唯一约束冲突）时才要求 `--force`（实体去重、Token 撞名自动改后缀）；
注意 MCP 会话缓存身份最长 30 分钟，改归属后应重启立即生效。

## 数据与安全

- 库内只存**提炼产物**（`infer=true` 路径）；`infer=false` 按需直存。
- **敏感内容按部署策略**（`SENSITIVE_MODE`，提炼层执行）：`allow`（默认，内网自托管定位）凭据/密码/密钥
  可按原文入库；`redact` 提炼时脱敏为「<类型>已脱敏（存放位置: …）」，公网/多人共享部署建议启用。
  `infer=false` 直存不经此策略（写入方自担）。
- **写入门槛与归属**：库定位跨机器/跨项目/长久记忆（配套 skill 引导分流：短期项目细节写项目内 AGENTS.md）；
  项目记忆带 `agent_id` 标签（MCP `add_memory` 与 REST `/v1` 均支持），可按项目检索、
  `DELETE /v1/memories/?agent_id=<项目名>` 批量清理。
- Token 校验走 sha256 哈希，**库内不存明文**：明文仅在创建响应里返回一次，丢失请吊销重建。
- 删除走单条确认（Web/MCP）或按作用域批量删（REST，必须带至少一个过滤条件）。

## 运维

- **个人规模 SQLite 余量充足**：10 万条记忆关键词检索 P95≈40ms；检索质量基线 recall@5=1.0 / MRR≈1.0
  （历史基线见 [docs/检索基线-2026-09-19.md](检索基线-2026-09-19.md)，注意其中 L0/L1/L3 相关项已随裁层失效）。
- 运维件：`npm run doctor`（首启自检）、`scripts/backup.sh` / `restore.sh`（在线备份恢复）、
  `scripts/export.js` / `import.js`（memories 全量迁移，幂等）、`npm run vec:rebuild`（换 embedding 模型后
  重建向量索引，`--user <id>` / `--all`）。
- Docker：多阶段镜像 + compose（数据卷 `./data`），见 [部署-生产机.md](部署-生产机.md)；
  操作手册见 [运维手册.md](运维手册.md)。
