# 生产机部署手册

> 目标机器：一台常驻的内网服务器（Linux）。本文只写本仓库真实存在的文件与行为，不架空。

## 1. 前置要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node | ≥ 20（建议 22 LTS） | `engines: >=20` |
| pm2 | 任意近期版本 | `npm i -g pm2`；`ecosystem.config.js` 已配好（`max_memory_restart: '512M'`） |
| 外网 | 仅 `npm install` 时需要 | 运行时不拉任何外链（前端零 CDN）；内网机可离线装（把 node_modules 一起拷过去） |

## 2. 首次部署（10 分钟）

```bash
git clone https://github.com/GGbao8848/aimemory.git && cd aimemory
git checkout feat/memory-atlas        # 或主分支
npm install                           # better-sqlite3 需编译；sqlite-vec 是 optional 依赖，装不上不阻塞
cp .env.example .env
```

编辑 `.env`，**必看项**（全部有默认值，但生产建议逐项确认）：

| 变量 | 说明 |
|---|---|
| `PORT` | 单端口承载 /mcp + /api + Web，默认 18543 |
| `PUBLIC_BASE_URL` | 对外地址（Web 生成 MCP 配置 JSON 的 url 字段用）；留空则用请求 Host |
| `AIMEMORY_PASSWORD` | Web 登录口令；**留空则首次启动自动生成并写回 .env**（启动日志会打印一次） |
| `LLM_ENABLED` / `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` | 素材提炼/摘要/凝练必需；任意 OpenAI 兼容 chat/completions 端点 |
| `EMBEDDING_ENABLED` | 语义召回可选；`0` 时检索自动退关键词（功能完整，召回少一路） |
| `L2_*` / `L3_*` | 冲突消解与凝练的开关与预算，默认全开（见 .env.example 注释） |
| `AIMEMORY_DB` / `AIMEMORY_L0_DIR` / `AIMEMORY_L3_DIR` | 数据落盘位置覆盖（默认都在 `data/` 下；一般无需动） |
| `AIMEMORY_L0_MAX_BODY` | L0 上传批次体积上限（默认 64mb；原始会话批次很大，勿调小） |

```bash
npm run doctor                        # 首启自检：依赖/目录/数据库/LLM 配置，缺什么给一行修复命令
pm2 start ecosystem.config.js && pm2 save
scripts/smoke.sh                      # 部署冒烟：healthz/登录/Token/MCP 握手/检索一条命令验完（失败非 0 退出码）
curl http://127.0.0.1:18543/healthz   # {"status":"ok","db":true,...}
```

浏览器打开 `http://<服务器>:18543/admin`（管理台，口令登录）。星图/样例前端已剪枝（2026-09-19），
产品主前端由独立仓库对接 `/api/*` 与 `/mcp`。

## 3. 采集器（其他机器的会话归档）

在各台要采集的机器上：安装本仓库的 `collector/`（pm2 常驻），配置服务端地址与 Token
（Token 在 `/admin` 签发）。采集器把 Codex / Claude Code / ZCode 的原始会话流式上传到
`POST /api/l0/ingest`（幂等：批次指纹 + 记录级去重，断点重传安全）。

部署前可先预览这台机器会采到什么（零副作用，不写 state、不上传）：

```bash
node collector/index.js --dry-run   # 游标从零起算的冷启动全量口径，输出各 agent 的批次/条数
```

配置方式（三选一，优先级从高到低）：环境变量 > `collector/.env`（从 `collector/.env.example`
复制，19 个参数全部有注释）> `~/.aimemory-collector/config.json`（安装流程写入）。
全部参数与默认值见 `collector/.env.example`。

## 4. agent 接入（MCP）

`/admin` 提供接入配置 JSON（Streamable HTTP）。核心配置形如：

```json
{ "mcpServers": { "aimemory": { "url": "http://<服务器>:18543/mcp", "headers": { "Authorization": "Token m0-xxx" } } } }
```

agent 拿到的工具共 10 个：记忆类 7 + 会话摘要 2 + `recall_context` 1（开场注入画像/约束/教训）。

## 5. 升级

```bash
cd aimemory
git pull
npm install          # 依赖有变时
pm2 restart aimemory-mcp
node --test          # 全量测试（契约一致性由 test/api-contract.test.js 守护）
```

schema 迁移全部幂等（启动时自动补列/建表），老库直接跑。

## 6. 回滚

```bash
git log --oneline -5                # 找上一个可用提交
git checkout <commit>
npm install && pm2 restart aimemory-mcp
```

数据回滚用备份（见 [运维手册](运维手册.md)）：**每次升级前跑一次 `scripts/backup.sh`**。

## 7. 备份

```bash
# crontab -e（每天 03:00，保留 14 份）
0 3 * * * /path/to/aimemory/scripts/backup.sh /path/to/data /path/to/backups 14
```

备份含 SQLite 在线快照 + L0 + L3，异地同步 `backups/` 目录即可。

## 8. 故障排查

| 症状 | 排查 |
|---|---|
| 进程反复重启 | `pm2 logs aimemory-mcp`；历史上是冷启动内存超限（采集器已改流式）；必要时调大 `max_memory_restart` |
| LLM 相关功能失效 | 服务有**半熔断**：连续失败自动熔断、每 60s 探测自动恢复，无需重启；`/healthz` 看 llm 字段 |
| 检索只有关键词结果 | embedding 不可用会自动降级（healthz 的 embedding 字段）；接上后 `POST /api/l2/vec/rebuild` |
| 端口被占 | `lsof -i :18543`；改 `.env` 的 PORT |
| 忘记 Web 口令 | 删 `.env` 里的 `AIMEMORY_PASSWORD` 行并重启 → 自动生成新口令打印在日志 |

## 9. 安全

- `data/` 含原始会话（最敏感），**目录权限等同密钥**；`.env` 已被 gitignore，密钥绝不入库。
- 数据库单文件 + WAL，随 `data/` 一起备份。
- 服务只暴露一个端口；如需公网访问，前面加反代并自行加 TLS。
