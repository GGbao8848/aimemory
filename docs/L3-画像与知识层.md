> 四层记忆的最内层。上游文档：[四层记忆架构与进展.md](四层记忆架构与进展.md)（§7 下一步）、[L2-事实记忆与冲突消解.md](L2-事实记忆与冲突消解.md)。

## 1. 定位与一阶段范围

L3 回答的问题与 L2 不同：L2 是「发生过什么」（大量、原子、可过期），
L3 是「**长期成立的是什么**」（少量、复合、随时间演化）——用户画像、项目约束、经验教训。

**一阶段只做骨架**（能用、可审阅、可回滚，避免一次做重）：

| 已做（一+二阶段） | 未做（明确不做/待定） |
|---|---|
| Markdown 文件存储（人工可直接编辑） | 结构化库/向量检索（条目量小，暂无必要） |
| 后台低频凝练（L1 摘要 → L3 条目，supersede 判定） | — |
| 时间推理（G5）：未生效（valid_from 在未来）条目不注入；排序用有效置信，久远条目自然沉底 | — |
| 双时间轴字段（valid_from / created_at + superseded_by） | — |
| REST 查询 / 人工编辑（`/admin`「L3 画像」视图）/ 手动触发 | — |
| MCP 上下文注入（`recall_context`，只读零 LLM） | — |
| 置信度时效衰减（只读视图，半衰 `L3_HALF_LIFE_DAYS` 天） | — |
| L2 事实采样参与凝练（仅作背景，提示词约束不照抄） | L2 事实的深度消解（待定） |

> 注：星图前端（atlas/）已于 2026-09-19 剪枝（用户定论：前端由外部仓库另行构建），
> L3 的 Web 出口为 `/admin`「L3 画像」视图；`/api/atlas/overview` 聚合接口保留。

## 2. 设计

### 2.1 存储：`data/l3/<kind>.md`

三种条目各一个文件，人工用任何编辑器都能改：

| 文件 | kind | 装什么 |
|---|---|---|
| `profile.md` | profile | 用户画像：身份、偏好、习惯 |
| `constraints.md` | constraints | 项目约束：环境、部署、资源等硬约束 |
| `lessons.md` | lessons | 经验教训：踩坑与结论 |

每条条目 = 一个元数据注释行 + markdown 正文：

```
<!-- l3 id=ab12cd34 valid_from=2026-09-18 created_at=… updated_at=… superseded_by= source=l1:zcode/s1 confidence=0.8 -->
生产环境部署在内网 10.10.10.x，embedding 服务是可选组件。
```

- **双时间轴**：`valid_from`（事实自何时为真）与 `created_at/updated_at`（何时入库/修改）分开记；
  被取代的条目**不删除**，标 `superseded_by=<新id>` 留在文件里——「以前的偏好是什么、何时变的」可追溯。
- **元数据值不含空格**（由写入端保证），正文随意——解析器只认注释行，人类怎么排版都不破坏解析。
- 服务端每次变更整文件重写（条目量级几十条，无性能问题）。

### 2.2 凝练流水线（低频是硬要求）

```
触发：新完成的 L2 派生 ≥ L3_BATCH_NEW（默认 5）个，或手动 POST /api/l3/run
输入：① 新完成的 L1 摘要（overview/decisions/artifacts，裁剪）
      ② 现有 active 的 L3 条目（让模型做取代判定）
调用：1 次 LLM（宁缺毋滥：没有值得沉淀的就返回空数组）
输出：[{kind, text, supersedes: <旧条目id|null>, confidence}]
应用：supersedes 有效 → 旧条目标 superseded_by；新条目 append 到对应文件；游标推进
```

- **为什么以 L1 摘要为主、L2 只少量参与**：L1 已把会话压成「目标/决定/产出物」，
  是性价比最高的凝练输入；L2 事实量大且多为易过期的原子事实，一阶段先不喂（省 token、防噪声）。
- **为什么触发挂在 L2 派生之后**：L2 的 done 数是「有多少新会话已被消化」的自然游标，
  复用它就不用新建会话级状态表；L3 游标只记 `last_consumed`（l2_sources 的最大 updated_at）。
- **幂等**：游标推进后同一批摘要不会重复凝练；LLM 失败 → 游标不动，下轮重试。

### 2.3 Token 预算

单轮凝练 ≈ 新摘要 8 条 × 300 字 + 现有条目 20 条 × 120 字 ≈ 3K token 输入，输出 ≤ 600。
默认 5 个新会话才跑一轮：**摊到每个会话约 0.7K token**。测试全部 stub。

## 4. 风险与开关

| 风险 | 应对 |
|---|---|
| LLM 凝练出低价值条目污染 L3 | 提示词「宁缺毋滥」+ confidence 字段 + 人工可编辑可删除 |
| 误取代旧条目 | superseded 只标记不删除，`superseded_by` 可清空复原 |
| 与人工编辑冲突（后台重写文件覆盖手改） | 后台只在「有新条目要落」时重写，且以解析后的内存态为准（手改会被先解析进来再合并） |
| 成本 | 低频触发 + 单次调用 + 硬裁剪 |

**开关**：`L3_DERIVE=0` 关闭后台凝练（存储与接口不受影响）。回滚 = 关开关 + 删 `data/l3/`（纯派生物，可再生）。

## 6. 验收结果（2026-09-18）

- **真实凝练**（deepseek-chat，1 次调用）：5 个已消化会话 → 4 条项目约束 + 1 条经验教训，
  confidence 0.8-0.9，`source` 记录了消费的会话；**没有编造任何"用户画像"**（素材里没有就输出空）——宁缺毋滥生效。
- **幂等**：带已有条目再跑一轮 → 模型输出空数组，0 重复入库。
- **落盘**：`data/l3/constraints.md`、`lessons.md` 人可直接读改；被取代条目留原文件标 `superseded_by`。
- **星图**：L3 内圈从虚环"待建"变实时环，节点显示真实条数；`/api/atlas/overview` 新增 `l2`/`l3` 字段。
- **Token**：本阶段真实 LLM 调用 **2 次**（凝练 1 + 幂等复跑 1），每次约 2K token。
- 测试基线从 127 项增至 **146 项，全绿**。
