# 前端对接指南

> 面向**管理台前端 `web/`**（Vite + React + TS + Tailwind v4 + shadcn/ui，同仓维护）与任何外部自建的客户端：
> 本服务是单用户自托管记忆库，所有数据归属 Token 持有者。两张对接面：**mem0 形态 `/v1` `/v2`**（对外接入）
> 与 **REST `/api/*`**（管理台自用）。契约：`GET /api/openapi.json`（路径+方法集守护）；类型：`docs/api/aimemory-api.ts`
> （`npm run types` 生成，`web/src/api/contract.ts` 直接引用——后端路由漂移会让前端 `tsc` 与契约守护测试同时失败）。

## 1. 鉴权

| 场景 | 方式 |
|---|---|
| agent / 机器到机器 | 请求头 `Authorization: Token m0-xxx`（与 mem0 相同；Token 在 `/admin`「接入 Token」页签发） |
| 浏览器（管理台） | `POST /auth/local-login`（表单 `password`）→ 302 + `aim_session` cookie（HttpOnly，7 天） |
| 未鉴权 | 一律 `401 {"error": ...}` |

登录页自带暴力防护：同一 IP 15 分钟内错 10 次锁 15 分钟（429）。

**user_id 语义**：个人部署，记忆归属鉴权主体——`user_id` 必须省略或与之相等（传别的值 403）；
省略时默认主体。`agent_id` / `run_id` 是自由标签维度，随意使用。

## 2. 写入语义（最重要的约定）

`infer=true`（默认）时**返回 ≠ 已入库**——素材异步受理：

```bash
POST /v1/memories/ {"messages":[...], "user_id":"owner"}   # → 200 {"event_id":"…","status":"pending"}
GET  /v1/event/{event_id}/                                 # → 轮询至 done / failed
```

- `done`：`result.count` 条提炼产物；`failed`：`error` 说明原因，素材未入库。
- 后台 LLM 提炼会做**冲突消解**（ADD/UPDATE/DELETE/NOOP）：重复事实不会反复入库；
  「更新取值」会取代旧记忆；每次变更写入 history（`GET /v1/memories/{id}/history/`）。
- `infer=false`：原文直存，同步返回 `{results:[{id, memory, event:"ADD"}]}`，不经 LLM
  （`LLM_ENABLED=0` 时仍可用）。
- `LLM_ENABLED=0` 时 `infer=true` 写入直接拒绝（503）——前端应禁用相应入口。

## 3. 检索与列表

```bash
POST /v2/memories/search/ {"query":"网关在哪","filters":{"user_id":"owner"},"top_k":5}
POST /v2/memories/ {"filters":{"agent_id":"zcode"},"page":1,"page_size":20}
```

- filters 支持：实体维度（user_id/agent_id/run_id）、`metadata` 键值、`created_at`/`updated_at`
  的 `{gte,lte}` 范围、`keywords` 文本包含；`AND` 数组展开合并；OR/NOT 明确报 400（不做静默错结果）。
- search 响应：`{results:[{id, memory, score, user_id, agent_id, run_id, metadata, created_at, updated_at}]}`。
- get_all 响应：`{count, next, previous, results}`（分页 URL 形状同 mem0）。

## 4. 变更 / 删除 / 历史

```bash
PUT    /v1/memories/{id}/  {"text":"…"}          # 更新（改文本后异步重消解）
DELETE /v1/memories/{id}/                        # 单条删除
GET    /v1/memories/{id}/history/                # ADD/UPDATE/DELETE 留痕（新→旧）
DELETE /v1/memories/?agent_id=zcode              # 按作用域批量删（异步，'*'=全选该维度；至少一个条件）
```

错误形状统一为 `{"error": "人可读中文"}`。

## 5. 管理台自用面（/api/*）

`web/` 前端消费的接口，外部前端可不用：

| 接口 | 说明 |
|---|---|
| `GET /api/me` / `/api/stats` | 身份 / 统计（memories + keys 计数） |
| `GET /api/memories?page=&page_size=&q=` | 管理台列表（q 走混合检索；内部形状 text 字段） |
| `PATCH/DELETE /api/memories/{id}` | 编辑 / 删除（同 /v1 语义） |
| `GET /api/memories/export` | 导出全部记忆（JSON 附件） |
| `GET /api/events/{id}` | 素材提炼事件状态（管理台轮询用） |
| `GET/POST /api/keys`、`POST /api/keys/{id}/revoke` | Token 管理 |

## 6. MCP（agent 面）

Streamable HTTP：`POST /mcp`，头 `Authorization: Token m0-xxx` + `Accept: application/json, text/event-stream`。
握手序列：`initialize`（响应头带 `mcp-session-id`）→ `notifications/initialized` → 携会话头 `tools/list` / `tools/call`。
7 个工具：`add_memory` / `get_event_status` / `search_memories` / `get_memories` / `get_memory` /
`update_memory` / `delete_memory`。业务错误以 `isError:true` 结果返回且文案可自愈（不是协议错误）。

## 7. 最小链路示例（登录 → 签发 → 检索）

```bash
BASE=http://127.0.0.1:18543
# 登录取 cookie
curl -c jar -d "password=$PW" $BASE/auth/local-login          # 302
# 签发 Token（明文仅此一次出现在响应里）
curl -b jar -H 'Content-Type: application/json' -d '{"name":"front"}' $BASE/api/keys   # 201 {"token":"m0-…", ...}
# 检索
curl -H "Authorization: Token m0-xxx" -H 'Content-Type: application/json' \
  -d '{"query":"部署","filters":{"user_id":"owner"}}' $BASE/v2/memories/search/
```

```ts
import { API_ROUTES, type Mem0Memory, type Mem0HistoryEntry } from './docs/api/aimemory-api';
// API_ROUTES 是路由面唯一来源（与后端契约守护同步）；实体形状见 Mem0Memory / Mem0HistoryEntry 等。
```

## 8. 生成与守护

- 类型/路由面：`npm run types`（从 openapi.json 生成 `docs/api/aimemory-api.ts`，幂等无时间戳）。
- 守护：`test/api-types.test.js`——生成物与 openapi 不同步、漏路径、实体接口缺失都会红。
- 改动后端接口时：先更 `docs/api/openapi.json`（契约测试强制）→ `npm run types` → 同步本手册。
