# 前端对接指南

> 面向**管理台前端 `web/`**（Vite + React + TS，同仓维护）与任何外部自建的浏览器端：本服务是单用户自托管记忆库，
> 所有数据归属一个身份，无需登录态切换/多租户逻辑。两张对接面：**REST `/api/*`**（管理面）与 **MCP `/mcp`**（agent 面）。
> 契约：`GET /api/openapi.json`（路径+方法集守护）；类型：`docs/api/aimemory-api.ts`（`npm run types` 生成，
> `web/src/api/contract.ts` 直接引用——后端路由漂移会让前端 `tsc` 与契约守护测试同时失败）。

## 1. 鉴权

| 场景 | 方式 |
|---|---|
| agent / 机器到机器 | 请求头 `Authorization: Token m0-xxx`（Token 在 `/admin`「接入 Token」签发，或走设备流 §5） |
| 浏览器（管理台/前端页） | `POST /auth/local-login`（表单 `password`）→ 302 + `aim_session` cookie（HttpOnly，7 天） |
| 未鉴权 | 一律 `401 {"error": ...}` |

登录页自带暴力防护：同一 IP 15 分钟内错 10 次锁 15 分钟（429）。

## 2. 写入语义（最重要的约定）

**返回 ≠ 已入库**。所有写入都是「素材异步受理」：

```bash
POST /api/memories {"text": "……"}     # → 202 {"event_id":"…","status":"pending"}
GET  /api/events/:id                  # → 轮询至 done / failed
```

- `done`：`result.count` 条提炼产物 + `result.ops`（added/updated/deleted/noop——noop>0 说明
  素材内容库中已有，不是空产出）；`failed`：`error` 说明原因，素材未入库。
- 后台 LLM 提炼会做**冲突消解**：重复事实不会反复入库；「更新取值」会取代旧记忆（DELETE=删旧+存新）。
- `LLM_ENABLED=0` 时写入直接拒绝（503）——部署未配 LLM 时前端应禁用写入入口。

## 3. 检索与列表

```bash
GET /api/memories?q=关键词&page=1&page_size=10        # 列表（q 走混合检索，语义+关键词+OR 兜底）
GET /api/memories?filters={"metadata":{"source":"zcode"},"updated_at":{"gte":"2026-09-01"}}
POST /api/memories/{id} 的 PATCH                       # 改文本/元数据（改文本后台自动去重合并）
DELETE /api/memories/{id}                              # 单条删除（有确认语义，前端务必二次确认）
```

错误形状统一为 `{"error": "人可读中文"}`；分页字段：`total/page/pageSize`。

## 4. 各层数据速查

| 层 | 接口 | 说明 |
|---|---|---|
| L0 归档 | `GET /api/l0/stats`、`/api/l0/session?agent=&device=&session_id=` | 原始会话（只读） |
| L1 摘要 | `GET /api/l1/summaries?device=&agent=`、`/api/l1/stats`、`POST /api/l1/run` | 「某会话/某机器做了什么」 |
| L2 事实 | `GET /api/l2/stats`、`/api/l2/ops`（四操作审计）、`/api/l2/sources` | 消解明细 applied=0 为拦截 |
| L3 画像 | `GET /api/l3/entries`、`GET /api/l3/history`、`PUT /api/l3/entries/:id`、`POST /api/l3/run` | 变更链可视化用 history |
| 聚合 | `GET /api/stats`、`/api/me`、`/healthz`（queue 积压字段） | 首屏/健康 |

## 5. 设备流接入（免粘贴签发 Token）

```
1. agent 端：POST /api/connect/start            → { authorize_url, request_id }
2. 浏览器：打开 authorize_url → 口令登录 → 填 Token 名 → 确认（或带 confirm_token 免按钮自动关窗）
3. agent 端：轮询 GET /api/connect/poll?request_id=…  → authorized 后返回 { token, key_name }
```

## 6. MCP（agent 面，可选了解）

Streamable HTTP：`POST /mcp`，头 `Authorization: Token m0-xxx` + `Accept: application/json, text/event-stream`。
握手序列：`initialize`（响应头带 `mcp-session-id`）→ `notifications/initialized` → 携会话头 `tools/list` / `tools/call`。
10 个工具清单与语义见 README「特性」节；**业务错误以 `isError:true` 结果返回且文案可自愈**（不是协议错误）。
`recall_context` 支持只取指定类别：`{"kinds": ["constraints","lessons"]}`。

## 7. 最小链路示例（登录 → 签发 → 检索）

```bash
BASE=http://127.0.0.1:18543
# 登录取 cookie
curl -c jar -d "password=$PW" $BASE/auth/local-login          # 302
# 签发 Token（明文仅此一次出现在响应里）
curl -b jar -H 'Content-Type: application/json' -d '{"name":"front"}' $BASE/api/keys   # 201 {"token":"m0-…", ...}
# 检索
curl -H "Authorization: Token m0-xxx" "$BASE/api/memories?q=部署&page=1"
```

```ts
import { API_ROUTES, type Memory, type EventStatus } from './docs/api/aimemory-api';
// API_ROUTES 是路由面唯一来源（与后端契约守护同步）；实体形状见 Memory/EventStatus 等。
```

## 8. 生成与守护

- 类型/路由面：`npm run types`（从 openapi.json 生成 `docs/api/aimemory-api.ts`，幂等无时间戳）。
- 守护：`test/api-types.test.js`——生成物与 openapi 不同步、漏路径、实体接口缺失都会红。
- 改动后端接口时：先更 `docs/api/openapi.json`（契约测试强制）→ `npm run types` → 同步本手册。
