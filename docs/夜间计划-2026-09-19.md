## 0. 产品视角（用户 01:35 追加：先想清楚最终用户怎么用）

**最终用户**：一个拥有多台机器、多个编码 agent（Claude Code / Codex / ZCode）的个人。
产品的正确形态是「**装完即忘，偶尔看一眼，agent 自动变聪明**」：

1. **安装即用**：`node src/index.js` → 口令自动生成 → 打开 Web 就是星图；/admin 有 MCP 接入配置。
   易用性红线：不允许"必须读文档才能接入"。
2. **日常零操作**：采集器自动归档 → 后台静默提炼/摘要/凝练 → 记忆自动生长。用户唯一要做的偶发动作：
   打开星图看状态、在 admin 审计"它记了什么/删了什么"、偶尔改 L3 条目（markdown 直接编辑）。
3. **agent 自动受益**：MCP 工具是唯一给 agent 的面——工具必须少而清晰、错误信息可自愈、
   `recall_context` 一个调用就能拿到"我是谁/环境约束/教训"。
4. **易用性的度量**：环境开关少而语义清晰；接口行为可预测（契约守护）；坏了能自愈（熔断自动恢复）；
   一切"高级能力"都必须有开关且默认关闭。

**官方最佳实践调研（01:35，网络受限仅两源可达）**：
- mem0 官方：先简单后特性；用元数据过滤做结构化查询；重排（rerank）提升相关性；
  用 custom instructions 控制事实抽取粒度（本项目对应：extractMemories 的提示词）。
- MCP 官方规范：① 输入校验错误应是**工具执行错误**（isError:true + 模型可自愈的行动建议），
  而非协议错误（-32602，模型无法修正）——本项目当前用 McpError 抛协议错误，**需改**；
  ② 工具清单顺序应确定（已满足，静态数组）；③ 工具可带 title（人可读名，未用，顺手补）；
  ④ 产错误信息要给"下一步怎么改"（如"必须在未来。当前日期是…"）。
- sqlite.org 经 7890 代理可达（官方 FTS5 文档已抓取）：**少于 3 个 unicode 字符的子串在全文查询中不匹配任何行**（官方原文确认，正是本项目 JS 兜底路径存在的原因）；trigram 支持子串/短语/AND/OR 匹配；bm25 数值越低越好（本实现 ORDER BY score 升序已正确）；还支持索引化 LIKE/GLOB。
- 用户告知：**本机 127.0.0.1:7890 通外网**（已记入长期记忆），后续外网调研/下载走该代理。
