# aimemory 记忆使用准则

aimemory 是企业的共享记忆层：**你在一次会话里学到的、值得长期保留的事实，写进去；下次任务开始时，先查有没有可复用的记忆。** 记忆按登录用户隔离——你写的内容只有你能读到，反之亦然。

## 工具速查

| 工具 | 用途 |
|---|---|
| `add_memory(text, metadata?)` | 写入一条记忆（非空文本，可带 metadata 如 `{"source":"claude-code"}`） |
| `search_memories(query)` | 按关键词检索（支持中文子串，查询建议 ≥3 字符） |
| `get_memories(page_size?)` | 分页列出自己的记忆 |
| `get_memory(memory_id)` | 按 id 取单条（含修改历史） |
| `update_memory(memory_id, text?)` | 修正内容（旧值自动进历史） |
| `delete_memory(memory_id)` | 删除（旧值进历史） |

## 什么时候该写（写入时机）

满足以下任一，就值得 `add_memory`：

- **部署/环境经验**：完成一次安装、配置、联调，把"怎么做 + 关键参数 + 踩过的坑"写下来（例如："生产环境 Keycloak 在 18443 端口，管理员密码在 mykeycloak/.env"）
- **踩坑记录**：解决了某个报错/疑难问题，记录根因与解法，避免下次重踩
- **项目约定**：命名规范、架构决策、端口规划、目录约定
- **用户偏好**：用户明确表达的偏好（"我习惯用 XX"、"这个项目用 YY 部署"）
- **重要事实**：账号位置、服务地址、版本约束等用户可能再次问起的信息

写入时遵循：
- **一句话讲清**，像给未来的自己留的便签；保留关键细节（端口、路径、版本）
- 可带 `metadata` 分类，如 `{"source":"claude-code", "topic":"keycloak"}`
- 一次写一条，不要为了凑数写入临时性/易变内容

## 什么时候该查（检索时机）

开始新任务、换项目、用户提到"上次/之前/以前"时，**先 `search_memories` 再动手**：

- 新任务开始：查相关关键词（项目名、技术栈、服务名）
- 遇到和过去相似的问题：查解法是否已在记忆中
- 用户问"之前是怎么做的/部署在哪"：直接查记忆回答

检索技巧：
- 用**核心名词**当关键词（如 `Keycloak 端口`、`数据库迁移`），不用整句话
- 一次查不到就换同义词/拆词再查（如查"数据库"没中，试"postgres"）
- `search_memories` 是关键词检索（无向量语义），请用记忆中可能出现的**字面词**

## 什么时候该改/删

- 记忆内容过时了 → `update_memory` 修正，不要另存一条新的
- 记忆错了 → `update_memory` 或 `delete_memory`
- 写入时发现之前写过同类 → 先 `search_memories` 查出来再 `update_memory` 合并，避免重复

## 安全红线（重要）

- **绝不写入密码、API 密钥、证书私钥等敏感明文**——记忆库靠 API Key 鉴权隔离，但内容本身不是保险库；涉及凭据时只记"凭据在哪"（如"密码在 .env"），不记密码本身
- 记忆内容默认只有自己可见，但**不要假定绝对安全**：内网可及的内容按公司保密等级判断是否入库
- 用户明确要求删除记忆时，用 `delete_memory` 立即执行

## 给用户的引导

- 用户首次使用：引导运行 `/aimemory-connect`（浏览器一键授权，密钥自动生成并写入配置）；该命令不可用时提示去 Web 平台（`http://<服务器>:18543`）登录生成 API Key，运行 `/aimemory-key` 手动引导
- 用户问"你记得…吗"：先查记忆再回答，查不到就如实说"记忆中还没有"
- 记忆工具报 401/连接失败：提示检查 API Key 是否有效（可在平台重新生成）或服务是否在线（`/aimemory` 可检查状态）
