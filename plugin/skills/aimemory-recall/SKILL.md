# aimemory-recall（记忆上下文加载）

从 aimemory 记忆库检索与当前任务相关的记忆，注入上下文。核心逻辑由 MCP 服务提供（`mcp__aimemory__search_memories`），本 skill 只描述编排。

> ⚠️ 依赖已连接的 MCP 服务 `aimemory`（`http://<内网IP>:18543/mcp`，工具前缀 `mcp__aimemory__`）。
> ⚠️ 本 skill 是**只读**的——只检索，不修改、不删除任何记忆。

## 何时使用

- 用户开始一个新任务、切换项目或上下文时
- 用户说"之前/上次/以前/我记得/我们讨论过"之类的话
- 处理涉及历史决策、偏好、配置、踩坑经验的任务
- 复杂多步骤任务开始时，主动预取相关记忆
- 任务涉及用户个人偏好（如"我习惯用 X"）或团队约定时

## 执行步骤

1. **提取主题**：从当前用户消息/任务中提取关键词——文件名、模块名、功能领域、技术栈、人名、项目代号。

2. **并行检索**：按 2-4 个角度调用 `mcp__aimemory__search_memories`（尽量并行，各取 top 5）：

   | 查询角度 | 示例查询 | 目的 |
   |---|---|---|
   | 项目/模块名 | `"aimemory 部署"` / `"bip 报工"` | 项目架构与配置 |
   | 技术/工具 | `"pm2 管理"` / `"embedding 服务"` | 技术决策与偏好 |
   | 用户提及的实体 | 用户刚提到的文件名/人名 | 相关背景 |
   | 宽泛上下文 | 任务的一句话总结 | 兜底召回 |

3. **去重合并**：按记忆 id 去重，合并所有查询结果。

4. **输出紧凑上下文块**（最多 10 条，只输出与当前任务真正相关的）：

   ```
   [aimemory 记忆] 已加载 <N> 条相关记忆：
     • <记忆内容> [id: <短id>]
     • <记忆内容> [id: <短id>]
   ```

5. **零结果时保持沉默**：不输出空上下文块，不声明"没有找到记忆"。

## 约束

- **只读**：绝不调用 `add_memory`/`update_memory`/`delete_memory`/`delete_all_memories`/`delete_entities`
- **最多 10 条**：只保留最相关的，避免污染上下文
- **静默于空**：无相关记忆时不打扰用户
- **融合不引用**：把记忆内容融入回答，除非用户要求，不逐条罗列来源
- 记忆内容可能是历史快照，**使用前判断其时效性**（如涉及密码/端口可能已变更），必要时提醒用户核实
