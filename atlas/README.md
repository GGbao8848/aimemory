# 记忆星图（Memory Atlas）

`atlas/` 是 aimemory 的前端：把「四层记忆 + 各模块 + 线路通讯状态」画成一张**活体概念图**，
不是传统的列表式管理台。打开 `http://<服务地址>:18543/` 即是它（原管理台挪到 `/admin`）。

```
┌─ L0 原始会话归档 ────────────────────────────────────────┐
│  各机采集器 ──► /api/l0/ingest ──► data/l0/**/*.jsonl    │
└──────────────────────────┬───────────────────────────────┘
                           │ 静默 5min + 指纹判变
┌─ L1 会话摘要 ────────────▼───────────────────────────────┐
│  调度器 → 预算化压缩 → LLM → l1_summaries                │
└──────────────────────────────────────────────────────────┘
                           MCP 客户端
                              │ add_memory(素材)
┌─ L2 事实记忆 ───────────────▼────────────────────────────┐
│  events 队列 → LLM 提炼 → 冲突消解 → memories              │
└──────────────────────────┬───────────────────────────────┘
                           │ 低频凝练（攒够 5 个新会话）
┌─ L3 画像／知识 ──────────▼───────────────────────────────┐
│  data/l3/*.md · 双时间轴 · 人工可编辑                      │
└──────────────────────────────────────────────────────────┘
```

## 怎么读这张图

- **同心环＝记忆层级，由外向内是「由原始到凝练」**：外圈 `L0 原始会话归档`（append-only 唯一事实源）
  → `L1 会话摘要` → `L2 事实记忆` → 内圈 `L3 画像／知识`（双时间轴，长期凝练）。
  环上的徽标（`L2 事实记忆` 等）就是层级标签，点一下只看这一层。
- **中心是存储内核**（SQLite 单文件库）：`memories` / `l1_summaries` / `l0_records` / `events` 都落在它里面。
- **线路上的光点就是数据流**：点密度与流速随**真实遥测**变化——L0 最近上传越久，采集链越暗越慢；
  `events` 队列有积压，沉淀链就变亮；LLM/Embedding 探活失败，对应外部节点转红、星云整体偏红。
- **节点右下角是实时数字**（记忆条数、归档体积、摘要进度…），来自 `/api/atlas/overview` 与 `/healthz`。
- **未登录时自动切演示数据**，左上角角标会写明「未登录 · 演示数据」，不会假装是真实值。
  登录（`/auth/login?next=/`）后角标变「实时数据」。

## 交互

| 操作 | 效果 |
|---|---|
| 拖拽 | 平移 |
| 滚轮 | 以光标为锚点缩放 |
| 双击 / `R` | 视角复位 |
| 点击节点 | 右侧检视面板：职责、实现文件、接口、关键参数、上下游、要点 + 实时数字 |
| 点击环上徽标 / 左侧图例 | 只看该层级（再点取消） |
| 底部「① 采集归档 / ② 记忆沉淀 / ③ 记忆召回」 | **链路追踪**：把一次请求逐跳演一遍，非当前步压暗 |
| 追踪中 `←` `→` / `空格` / `Esc` | 上一步 / 下一步 / 暂停 / 退出 |
| `1` `2` `3` | 直接开始对应追踪 |
| `P` | 暂停/恢复动画 |

## 目录结构

```
atlas/
  index.html          骨架与 HUD 容器
  atlas.css           HUD 皮肤（玻璃面板 / 发丝描边 / 环带徽标 / 响应式）
  js/
    main.js           入口：遥测 → 图形状态 → 渲染，交互与相机
    topology.js       ★ 拓扑事实源：节点 / 线路 / 追踪脚本（对着 src/ 的真实实现写）
    graph.js          极坐标 → 世界坐标、贝塞尔线路、节点尺寸
    telemetry.js      遥测轮询 + 演示数据兜底 + 繁忙度推导
    renderer.js       WebGL2 渲染（背景 / 线 / 节点 / 数据包 / Bloom）
    gl/
      glutil.js       程序编译、FBO、动态缓冲
      shaders.js      全部 GLSL
    ui/
      hud.js          顶部状态灯与指标、左侧层级图例、底部通讯日志
      labels.js       节点标签与环带徽标（含去重叠）
      inspector.js    右侧模块检视面板
      trace.js        链路追踪编排
```

零依赖、零构建：纯 ESM + 手写 GLSL，静态文件直接由 Express 提供。内网离线部署不拉任何外链。

## 渲染管线

单个 WebGL2 上下文，四段式：

1. **背景星云** → 默认帧缓冲：FBM 域扭曲星云 + 三层视差星场 + 雷达扫掠，
   色调随系统健康度漂移（正常偏蓝、有服务不可用偏红）。自带暗角/颗粒/抖动去色带。
2. **环 / 线路 / 节点 / 数据包** → HDR FBO（加法混合，亮部不截断）。
3. **亮部提取 + 两级分离高斯模糊**（1/2 与 1/4 分辨率）。
4. **合成** → 加法叠回背景：ACES 色调映射 + 色差。

不支持 `EXT_color_buffer_float` 时自动退 8bit（Bloom 降级但不空白）；
不支持 WebGL2 时显示明确提示并给出 `/admin` 入口。

## 改这张图

- **加/改模块**：只动 `js/topology.js` 的 `NODES` / `LINKS`。`angle`（角度制，0°=正东，逆时针为正）
  决定方位，`radius` 决定落在哪一环，`info` 里的字段会直接渲染到检视面板。
  方位尽量沿径向往外排：标签会朝圆心外侧摆，各环标签因此落在各自的外侧环带里。
- **加一层**：往 `RINGS` 加一条，并给 `RING_BADGE_ANGLE`（在 `js/ui/labels.js`）指定一个没被
  该环节点占用的方位角。
- **改链路追踪的解说**：`js/topology.js` 的 `TRACES`，每步 `nodes` / `links` / `title` / `detail`。
  设备是运行时生成的（`device:N`），引用不存在的 id 会自动忽略。
- **接新指标**：`telemetry.js` 的 `derive()` 把原始数字翻译成「线路繁忙度」；
  节点上的数字用 `NODES[].metric` 指定取值路径。

## 调试与验收钩子

页面上暴露了 `window.__atlas`（自托管个人服务，无敏感面）：

```js
__atlas.camera()        // 缩放/相机/安全区相关数值
__atlas.model           // 当前遥测快照（含 derived 繁忙度）
__atlas.graph           // 图数据
__atlas.tick(n)         // 手动推进 n 帧（不依赖 rAF）
__atlas.remeasure()     // 重测标签尺寸并立即重排
__atlas.labelOverlaps() // 标签重叠检测，返回重叠对
__atlas.layoutDump()    // 布局模型坐标 vs DOM 实测坐标对比
__atlas.trace()         // 当前追踪步的高亮节点/线路
```

`tick/remeasure/labelOverlaps` 是为了让自动化验收不依赖 rAF：
后台标签页里 rAF 会被浏览器节流到几乎不触发，直接截图会拿到过期画面。

## 已知取舍

- **标签去重叠只沿纵向**：横向位置绑定「节点在哪一侧」，动了就找不到归属；
  同侧标签用单向叠放扫描错开。极密集时会牺牲个别标签与节点的贴近度，换取整体可读。
  实测 26 个标签在中文字体下有 0-2 处 ≤10px 的边缘相接。
- **MCP 调用量没有埋点**，召回链路的繁忙度给的是中性基线（`derive().recall`），
  不是实测值——面板里不假装它是真的。
- **节流环境下开场动画**：`/` 在后台标签页加载时 rAF 几乎不跑，
  所以 2 秒后会无条件把缩放落到目标值，避免用户切回来看到放大且裁切的画面。
